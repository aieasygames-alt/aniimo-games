# Aniimo.games Content Expansion Plan

Last updated: 2026-09-02

## Goal

Expand Aniimo.games from a broad pre-launch wiki into a durable search-intent hub. New content should answer real user questions, preserve source trust, and avoid thin or overconfident pages while Aniimo facts are still changing.

## Version Roadmap

### V1: Launch Intent And Safety

Focus on searches that appear around launch: release timing, download access, redeem codes, server status, known issues and unsafe third-party files.

Ship and maintain:

- Aniimo server status
- Aniimo known issues
- Aniimo codes not working
- Aniimo download not available
- Aniimo store page not visible
- Aniimo pre-registration not working
- Aniimo APK safety
- Aniimo torrent safety
- Aniimo beta key safety
- Aniimo official website and links

Success criteria:

- Each page has a direct answer, official-source path, freshness signal and at least two related internal links.
- High-risk pages route users toward official storefronts and do not recommend mirrors, torrents, account sales or unofficial keys.
- Live issue pages separate confirmed issues from watchlist entries.

### V2: Platform Intent

Focus on "can I play Aniimo on X" searches and adjacent compatibility questions.

Ship and maintain:

- Steam, Epic Games Store, PS5, Xbox, iOS, Android and mobile pages
- Nintendo Switch status
- PS4 status
- Game Pass status
- Steam Deck status
- Crossplay
- Cross-save
- Controller support
- System requirements

Success criteria:

- Every platform-status page states confirmed status, unconfirmed status and where to verify.
- Unconfirmed platforms do not appear as supported in metadata or body copy.
- Download, launch and platform pages link to each other consistently.

### V3: Database Depth

Focus on converting the Aniimo database from index coverage into distinct, useful detail content.

Shipped first:

- Hand-authored detail-note overrides for 10 featured Aniimo already prioritized in the primary sitemap: Emberpup, Inferlupa, Glacy, Eklue, Skippy, Susuta, Fragrancier, Wisptis, Helgon and Cozite.
- Each featured override strengthens location notes, evolution detail, ability use case, related route logic and source notes without publishing unverified routes or balance claims.

Continue to maintain:

- Featured detail expansion for the 10-20 highest-interest Aniimo entries
- Aniimo character list
- Aniimo creatures and monsters
- Aniimo evolution list
- Aniimo locations
- Aniimo elements guide
- Aniimo roles guide
- Best Aniimo watchlists

Success criteria:

- Featured detail pages include location status, evolution detail, ability use case, beginner value, related entries and source notes.
- Collection pages avoid final strength, spawn or rarity claims until launch verification exists.
- Internal links connect detail pages by element, role, stage, region and evolution family.

### V4: Gameplay And Mechanics Authority

Focus on answer-first mechanics pages that are useful for both traditional SEO and AI citation.

Ship and maintain:

- Aniimo gameplay
- Aniimo combat
- Aniimo solo play
- Aniimo open world
- Twine
- Egg Heist
- Homeland
- Aniipod
- First hour guide
- Beginner mistakes
- Best settings

Success criteria:

- Each page starts with the user's question and separates confirmed facts from verification-pending details.
- Mechanics pages link to launch verification, database entries, regions and glossary terms.
- Exact values, cooldowns, rewards and route requirements stay watchlist until sourced.

### V5: Comparison And Discovery

Focus on users who understand Aniimo through neighboring games and genre expectations.

Ship and maintain:

- Aniimo vs Pokemon-style creature collecting
- Aniimo vs Palworld-style open-world expectations
- Aniimo vs Genshin-style open-world expectations
- Aniimo vs Temtem-style online creature RPG expectations
- Games like Aniimo
- Is Aniimo like Pokemon?
- Is Aniimo open world?
- Is Aniimo multiplayer?
- Is Aniimo pay to win?
- Does Aniimo have co-op?
- Does Aniimo have PVP?

Success criteria:

- Comparison pages use factual matrices instead of unsupported claims.
- Competitor names are used to clarify user intent, not to imply feature parity.
- Pages link back into official Aniimo mechanics, platform and database pages.

### V6: International Core Entrypoints

Focus only on high-intent localized entry pages before attempting broad translation.

Shipped first:

- Spanish release date, download, codes, mobile and official website pages
- Portuguese release date, download, codes, mobile and official website pages
- French release date, download, codes, mobile and official website pages
- German release date, download, codes, mobile and official website pages

Current implemented entrypoints:

- Spanish: release date, download, codes and official website
- Portuguese: release date, download, codes and official website
- French: release date, game overview, download, codes and official website
- German: release date, game overview, download, codes and official website

Success criteria:

- Localized pages keep the Aniimo name unchanged and link to canonical English hubs.
- Machine-like full-site translation is avoided until there is evidence of sustained country or language demand.
- Future hreflang work should follow only after localized pages are stable.

### V7: Freshness And Monitoring

Focus on keeping expansion maintainable.

Ship and maintain:

- Content expansion matrix
- GSC query refresh watchlist
- Official source watchlist
- Launch evidence queues
- Blocking, warning and info audit categories
- Orphan-page and outdated-page checks

Success criteria:

- New pages record cluster, intent, fact status, source path, refresh trigger and internal links.
- Release checks fail on missing metadata, missing sitemap routes, weak topic content and missing assets.
- Time-sensitive pages get refreshed when official sources, storefronts, launch tests or Search Console data change.

The next optimization should improve crawler paths and CTR for pages already showing early demand rather than adding another broad page batch:

- Keep trust pages live and linked from the site index; use them to support source-safe claims, corrections and AI/rumor-sensitive searches.

## Implementation Rules

- Prefer adding topic objects to the existing content arrays before introducing new page components.
- Only create a standalone component when the page needs custom UI, tables or repeated interactive structure.
- Every new indexable page must be reachable from an existing hub, included in `fullSitemapRoutes()`, prerendered, and covered by `npm run check:content`.
- Every high-risk page must include an official-source path and a clear "do not use unofficial downloads or keys" safety note.
- Every launch-sensitive page should have a refresh trigger tied to official news, storefront changes, launch testing or GSC queries.
